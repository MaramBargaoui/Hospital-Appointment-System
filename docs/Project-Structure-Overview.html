Hospital Appointment System — Project structure

Purpose: Two-part web application: Angular UI + Spring Boot REST API. Data in a SQLite file. Authentication uses JWT with roles (Patient, Doctor, Receptionist, Admin).

Top-level layout

PathRole
backend/REST API (Java 17, Maven), security, JPA persistence
frontend/Single-page app (Angular 20), calls /api
README.mdVision: actors & future modules (appointments, doctors, …)
docs/This overview

Omit build caches when presenting source: frontend/dist/, frontend/.angular/cache/.

Backend (backend/)

  • pom.xml — Spring Web, Security, Data JPA, Validation, JWT (jjwt), SQLite JDBC
  • mvnw.cmd — Maven wrapper
  • src/main/resources/application.properties — port 8080, SQLite ./data/hospital.db, JWT & seeded admin
  • HospitalApiApplication.java — Spring Boot entry point
  • domain/ — User entity, Role enum
  • repository/ — UserRepository
  • api/auth/ — register, login, /me; DTOs; AuthService
  • api/admin/ — admin-only user CRUD under /api/admin/users
  • api/ — health check, global exception handler
  • security/ — JWT filter & service, UserPrincipal, user-details loading
  • config/ — security chain, CORS, data seed, SQLite folder helper
  • src/test/ — Boot tests; in-memory SQLite profile

Runtime DB file: backend/data/hospital.db when the API is started from backend/.

Frontend (frontend/)

  • package.json / angular.json — Angular 20; dev proxy to port 8080 for /api
  • proxy.conf.json — forwards /api to Spring
  • src/app/app.config.ts — router, HTTP client, auth interceptor
  • src/app/app.routes.ts — login, register, dashboard, users (admin)
  • src/app/auth/ — login & register pages, AuthService, guards, models
  • src/app/dashboard/ — post-login home
  • src/app/users/ — admin user management + UsersService

Dev request path

Browser → localhost:4200 (Angular) → relative /api/… → proxy → localhost:8080 (Spring). After login, requests include Authorization: Bearer ….

README vs. code today

In code: auth, JWT, roles, admin user directory, dashboard shell.

In README only (future): appointments, doctors, medical records, notifications, analytics.

Short structure guide for presentations — not a full specification.
